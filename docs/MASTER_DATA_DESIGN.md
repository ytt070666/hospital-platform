# 医院主数据设计（STEP 3）

## 边界

本阶段只管理医院、院区、楼宇楼层、临床科室、门诊科室、医生、职称、专业、出诊类型及其关系。没有排班、号源、预约、挂号、订单、支付、退款、病历或报告能力。

## 关系与规则

```text
医院 -> 院区 -> 楼宇 -> 楼层
医院 -> 临床科室（树） -> 门诊科室
医生 -> 医生职称
医生 <-> 临床科室（恰好一个主科室）
医生 <-> 医学专业
```

- 临床科室复用 `department`，绝不复用行政 `sys_department`。
- 科室树禁止自身及后代成为父节点；数据库和服务层都校验关联完整性。
- 医生创建和更新必须关联至少一个临床科室，且主科室必须位于关联集合中。
- 患者端仅见已启用、已发布、未删除记录；发布不等同于业务服务开放。
- 文件先经既有私有上传接口写入 MinIO，公开端仅能取得被已发布实体引用文件的短时读取地址。

## 权限、数据范围与审计

管理写操作使用 `hospital:*` 权限。科室与医生读取结合既有行政部门 DataScope：ALL、SELF、DEPT、DEPT_AND_CHILDREN、ORG、CUSTOM 的可见行政部门集合被编译为参数化 SQL 谓词。主数据写入由既有请求审计链路记录操作者、动作、时间、Trace ID 与访问路径。
