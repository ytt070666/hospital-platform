# 支付与退款体验流程（STEP 6.3）

患者在预约详情可看到收费义务的金额、支付截止时间和状态；患者中心提供“我的缴费”入口，按挂号订单和退款订单分别分页展示。金额始终由后端以分保存，前端仅以 `¥12.34` 形式展示，绝不由前端计算应收金额。

开发环境的能力接口只会在 TEST Provider 已配置时返回 `TEST`，页面才显示“创建测试支付单”。它只创建可审计的测试支付尝试，支付成功仍必须以经过校验的提供方回调或查询结果为准。微信、支付宝真实 SDK、商户密钥与真实扣款均不在本阶段实现。

退款来自已支付预约的取消、停诊或迟到支付补偿。患者只读查看退款编号、金额、原因和进度；财务人员可查看数据权限范围内订单，只有拥有 `hospital:refund:retry` 权限的人员能重试失败退款。重试写入审计事件，成功支付事实不会被退款操作覆盖。

## STEP 6.4 闭环

已支付预约取消后，页面保持支付成功事实，单独展示退款处理进度；退款成功后显示退款金额和剩余可退金额为零。退款失败由财务端受控重试，患者端只读同步最终状态。支付超时显示收费已关闭与预约已取消；迟到的真实支付确认后，预约不会恢复，而是显示退款结果。以上状态均由后端订单与退款接口返回，Web 和小程序使用同一患者 API。

真实微信、支付宝凭证未配置时，生产界面不会显示 TEST 通道或伪造可用的真实通道；开发环境的 TEST 提示只表示隔离测试能力。
