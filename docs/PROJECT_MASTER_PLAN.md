# 医院综合数字化服务平台：总体规划

> 版本：0.1（架构基线）  
> 阶段：STEP 1／规划；本文件不代表任何医疗诊疗功能已上线。

## 1. 建设目标与边界

建设统一的患者 Web、微信小程序与工作人员管理后台，三端只通过同一套 Hospital-Backend API 访问同一业务数据。第一期采用**模块化单体**，以清晰的领域边界、独立数据库迁移和接口契约支撑后续按需拆分；不预先引入 Spring Cloud、Nacos、Seata 等分布式复杂度。

平台定位为患者服务、运营管理、集成编排和数据治理层。HIS、EMR、LIS、PACS、RIS、医保等已存在的临床核心系统仍为其各自主数据源；本平台不在未经院方确认时重建电子病历、医嘱、处方审核或诊断决策。

## 2. 需求补全

除原始需求外，生产建设还需要：多院区/组织隔离、电子健康卡与主患者索引（MPI）匹配、知情同意与授权撤回、数据保留/归档/销毁策略、灾备与演练、主数据管理（科室/人员/字典）、投诉工单与服务评价、无障碍与适老化、预约候补通知、可观测性、配置变更审批、数据导出审批、接口目录与沙箱、业务连续性预案。

合规基线以《个人信息保护法》《数据安全法》《网络安全法》及医疗卫生机构数据管理、等保与院方所在地监管要求为准。上线前需由法务、信息科和安全部门确认适用等级与留存期限；本文不将其视为自动满足的法律结论。

## 3. 领域拆分

| 领域 | 责任 | 关键数据/边界 |
|---|---|---|
| IAM 与组织 | 账户、认证、RBAC、数据范围、二次验证 | 不保存患者诊疗正文 |
| 患者与健康卡 | 患者、就诊人、实名、家庭成员、MPI 映射 | 敏感身份信息加密 |
| 资源与排班 | 院区、科室、医生、门诊类型、号源 | 号源是预约唯一库存源 |
| 预约挂号 | 预约、取消、候补、登记、爽约 | 支付由订单域编排 |
| 订单支付 | 订单、支付、退款、对账、回调 | 金额只由服务端计算 |
| 报告与文件 | 结构化检查/检验报告、受控文件访问 | 报告事实源为 LIS/PACS/RIS |
| 患者服务 | 首页、CMS、导航、消息、问诊入口 | 内容与医疗数据分级隔离 |
| 住院与处方视图 | 已授权信息查询及外部系统映射 | 不替代 HIS/EMR/药学流程 |
| 集成中心 | Adapter、DTO、重试、幂等、对账 | 业务域不得直连第三方 SDK |
| 审计与运营 | 操作/访问/安全审计、指标、配置 | 审计日志防篡改、脱敏 |

## 4. 架构决策

- Java 21、Spring Boot 3、Spring Security、MyBatis-Plus、MySQL 8、Redis、MinIO、RabbitMQ、Vue 3、uni-app 为一期技术基线。
- 后端以 Maven 多模块模块化单体实现；领域模块只通过应用服务、领域事件和公开 DTO 协作，禁止跨模块直接访问 Mapper。
- Redis 用于验证码、限流、短会话、分布式幂等与号源原子预占；MySQL 保持最终业务事实和事务一致性。预约成功采用“Redis Lua 原子预占 + 数据库条件更新/唯一约束 + 失败补偿”的可验证方案，不能只依赖缓存。
- RabbitMQ 仅承载可异步重试的通知、审计投递、集成同步；交易核心路径不依赖最终一致消息才完成。
- 接口版本为 `/api/v1`；OpenAPI 由后端生成，客户端通过生成/共享类型消费，不手工复制接口定义。

## 5. 一期范围与非目标

一期优先交付认证授权、主数据、CMS、医生排班、预约挂号、订单支付适配、报告受控查询、消息、审计和基础集成框架。在线视频、医保结算、电子处方全流程、临床 EMR 编辑等只预留接口与权限模型，须完成独立合规、资质及供应商对接评审后立项。

## 6. 冲突检查与结论

1. “真实可部署”与“从零一次覆盖全部医院业务”冲突：以可部署的一期闭环和接口适配替代重建临床核心系统。
2. “实时排班”不能意味着三端各存一份数据：唯一写入为后台/同步任务，三端均实时读取同一 API。
3. 报告下载与隐私保护冲突：文件不公开，采用服务端鉴权与短期签名地址，访问必审计。
4. 医生可查看患者与最小权限冲突：必须由就诊关系、科室范围、有效期、用途和紧急访问流程共同约束，RBAC 本身不足以解决。
5. STEP 2 表清单同时出现 `sys_department` 与 `department`：二者分别定义为行政部门和临床科室主数据；本期仅建最小字段和编码关联，不合并建模。

## 8. 前置确认清单

进入编码前，院方需提供：组织/院区与科室主数据来源；HIS/LIS/PACS/RIS 厂商接口文档、测试环境和数据字典；支付商户与退款责任边界；实名/健康卡/医保接入授权；等保定级与日志留存要求；患者报告的可见范围、脱敏规则、紧急访问制度及部署网络拓扑。
