# 预约挂号体验与管理中心

## 患者预约流程

患者可从科室详情或医生详情进入同一个预约页面。页面读取公开排班接口中的真实剩余号源、院区、门诊类型和号段；选择排班、可用号段和本人就诊人后，使用单次预约尝试固定的 `Idempotency-Key` 创建 HOLD。公开排班 DTO 仅暴露预约展示所需的字段，绝不包含工作人员、版本或库存内部字段。

HOLD 页面只使用服务端返回的 `holdExpiresAt` 与 `serverNow` 计算倒计时。刷新、前后台切换、网络恢复和确认网络异常均重新读取预约详情，绝不再次创建 HOLD；倒计时归零会自动请求详情，使服务端落库的 EXPIRED 成为页面最终状态。确认或取消采用明确的就诊人、医生、日期与时段确认提示，确认后显示“预约成功”，不展示支付或缴费信息。HOLD 超时、号源不足、停诊、失效号段和重复预约分别展示可理解的提示，并要求重新读取排班。

患者可在“我的预约”按状态查询、查看详情以及取消 HOLD 或 BOOKED 预约。取消仅释放号源，不涉及退款。

若排班替诊，预约详情将实际出诊医生置于主信息，并明确显示“替诊医生，原出诊：某医生”；预约编号、就诊人、时间和库存不会变化。若排班停诊，患者刷新详情后得到已取消状态与停诊原因，不会继续显示可确认或可取消的有效预约。

BOOKED 状态的患者自助取消会由服务端按预约开始时间和医院取消截止配置判定；超过窗口时页面展示服务端拒绝结果，不通过前端时间判断绕过。工作人员使用后台“协助取消”时必须填写原因并留下审计、状态历史。

## 小程序

小程序使用相同的患者 API、预约状态语义和固定幂等键策略。添加就诊人后的返回路径保留原选择；进入预约详情和小程序重新显示时重新读取服务端预约信息并校正倒计时。`WECHAT_APPID=EXTERNAL`，因此本阶段不声明真实微信授权或真机验收。

## 后台预约管理

`/api/v1/admin/appointments` 提供服务端分页的列表、详情和授权取消操作。列表可按预约号、患者、就诊人（使用安全 Hash 精确匹配）、医生、科室、院区、门诊类型、排班与创建日期、状态过滤。详情含状态历史、库存摘要和审计记录；所有 DTO 均不返回加密字段、哈希值、令牌或 Redis 信息。查询在 SQL 中按排班所属行政科室接入 DataScope；无范围或越权详情一律拒绝。后台取消复用同一预约领域取消操作，状态历史写入 `STAFF` 操作方及原因、追踪号。

管理员权限：`hospital:appointment:list`、`hospital:appointment:view`、`hospital:appointment:cancel`、`hospital:appointment:history`。审计过滤器将后台预约详情和取消识别为 `APPOINTMENT` 资源。
